# OralCompass — data model and API

Eight data groups. Public groups are read-only catalogs built by `tools/ingest_sources.py` from `sources/extracted/*.json`; private groups
are owner-scoped records (`api/app/store.py`: every read goes through `repo.get_owned` → constant 404 on mismatch; audit events carry ids only).
Money is integer cents. Every value that reaches the UI carries an evidence status: DOC · USER · ASSUMED · AMBIGUOUS · UNKNOWN · CONFLICT.

## Calculation rules (deterministic, `engine/`)
- Normal code does the math; nothing is inferred from text at run time. The model may only extract and quote (`api/app/extraction.py`) and must pass the runtime lint.
- Missing input → `unresolved` with a named missing input, never a default. Unknown alternate allowance → plan payment is an upper bound. Unknown enrollment with a waiting period → two branches.
- Plans with separate out-of-network deductible/maximum need the member's separate out-of-network usage; "Unlimited" maximums remove both the cap and the input.
- Waiting periods are procedure-scoped when the document names procedure groups (`waiting_months.value` may mix procedure keys and class names; AMBIGUOUS scope is flagged on the line).
- Frequency clocks: calendar_count · interval_months · rolling12_count are enforced; per_tooth_months · per_quadrant_months are shown as rules only.
- Benchmarks never enter a calculation unless the user enters one as a hypothetical (ASSUMED).

## Ingestion and validation (`tools/`)
`ingest_sources.py` (facts → registry/evidence/codes/benchmarks/presets; validates ids, class rules, clocks, statuses, cite==fact quote, loader round-trip; `--check` for CI) ·
`audit_data.py` (inventory, missing fields, unsupported mappings, outdated documents, relationship integrity → `docs/DATA_AUDIT.md`) ·
`verify_citations.py` (quote-on-page check for stored PDFs) · `build_fictional_plans.py` (fictional PDFs + fixtures, labeled) · `seed_presets.py` (download + hash + verify real PDFs where the network allows).
Protocol for adding a source: `sources/RESEARCH_PROTOCOL.md` (open the document, quote exactly, record page/section/units/basis, mark unknowns, preserve conflicts, record reuse terms and access limits).

## Security (implemented vs planned)
Implemented: owner-scoped reads (constant 404), ids-only audit, presets read-only, redaction before model calls with a preview, document text treated as data (schema-only extraction), dev auth header only when `ORALCOMPASS_DEV_AUTH=1`, Cognito JWT validation path, export/delete.
Planned (infra/template.yaml): Cognito, API Gateway JWT authorizer, S3 SSE-KMS per-user prefixes with tenant encryption context, DynamoDB with CMK, EventBridge. Claims are limited to what is implemented: no certifications, no "zero knowledge", no "HIPAA compliant" (a BAA is required for PHI).
